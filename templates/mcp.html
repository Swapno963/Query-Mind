MCP

QueryMind is the MCP client. The restaurant JWT on the MCP server is the authority. QueryMind must not hide or invent tools.

1. One client, one server URL

An organization administrator saves the MCP server URL on Team. QueryMind then lists tools and calls them. ServeEasy’s URL is /mcp.

{% if mcp_server_url %}{{ mcp_server_url }}{% else %}Not set. Open Team and save the ServeEasy /mcp URL.{% endif %}
Typical values
# Local ServeEasy
http://127.0.0.1:8001/mcp

# Production ServeEasy
http://easyserve.clustorflow.com/mcp

Open Team to set mcp_server_url. Do not put a restaurant JWT in QueryMind settings — only the URL.

2. Forward the restaurant JWT

Staff chat sends the ServeEasy access token as X-MCP-Authorization. QueryMind copies it to Authorization: Bearer on tools/list and tools/call. No restaurant token → the MCP server returns 401.

Request — ask with MCP
curl -X POST {{ api_origin }}/api/v1/messages/ \
  --header "x-api-key: $QUERYMIND_API_KEY" \
  --header "X-MCP-Authorization: Bearer $SERVEEASY_ACCESS" \
  --header "content-type: application/json" \
  --data '{
    "content": "Show today's pending orders"
  }'
What QueryMind sends to /mcp
Authorization: Bearer $SERVEEASY_ACCESS
Content-Type: application/json
Accept: application/json

Mint the API key as the organization admin after the MCP URL is saved. Do not mint a Django superuser key for ServeEasy.

3. tools/list is filtered by the server

QueryMind uses whatever the MCP server returns. A waiter must not see create_menu_item. QueryMind has no restaurant-role allowlist.

JSON-RPC
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": {}
}
Waiter catalog
{
  "result": {
    "tools": [
      {"name": "list_orders"},
      {"name": "get_order"}
    ]
  }
}

4. tools/call is checked again

Hiding a tool is not security. The MCP server must deny names that were not listed. QueryMind still calls the selected name; ServeEasy returns permission_denied.

Allowed call
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "list_orders",
    "arguments": {"status": "PENDING", "date": "today"}
  }
}
Waiter calling create_menu_item
{
  "ok": false,
  "code": "permission_denied",
  "message": "You do not have permission to do that."
}

5. ServeEasy tools by job

Least privilege is by restaurant role, not by counting functions. Guests have no staff MCP — they use ServeEasy’s public menu and order HTTP APIs.

Role MCP tools QueryMind should see
Owner / admin All staff tools (orders, menu writes, status, pay)
Waiter list_orders, get_order
Chef Order reads + update_order_status
Cashier Order reads + mark_order_paid
Guest / diner None

6. Write confirmation

Menu writes, status, and mark paid return needs_confirmation and a confirmation_id. Treat that as a tool result, not a failure. Repeat the same arguments with confirmed: true and that id.

7. Tenant scope

The MCP server scopes data by user.restaurant_id on the JWT user, not only by role. QueryMind must not add a second permission table.

What not to do

  • Do not run waiter-mcp, chef-mcp, … — one server, filtered catalog.
  • Do not filter tools in QueryMind by restaurant role. ServeEasy JWT is the ACL.
  • Do not rely on the LLM “knowing” it must not call admin tools.
  • Do not advertise every tool and return 403. That wastes tokens and makes the model retry forbidden names.
