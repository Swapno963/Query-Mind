Authentication

Identity is the key. Health checks do not need a key.

Request
curl {{ api_origin }}/api/v1/workspace/ \
  --header "x-api-key: $QUERYMIND_API_KEY"
Example response
{
  "kind": "api",
  "engine": "postgres",
  "industry": "Retail / e-commerce",
  "business": "We sell online.",
  "keeps": ["orders"],
  "discovered_tables": ["orders"],
  "discovered_columns": {
    "orders": ["id", "status"]
  },
  "allowed_tables": ["orders"],
  "allowed_columns": {
    "orders": ["id", "status"]
  },
  "ready": true
}

Check {{ api_origin }}/api/v1/health without a key.

Errors

Failed requests return a typed error. Missing or invalid keys look like this.

Request
curl {{ api_origin }}/api/v1/workspace/
Example response
{
  "type": "error",
  "error": {
    "type": "authentication_error",
    "message": "Invalid API key."
  }
}

3. Profile (optional)

Tell QueryMind what the business does. Only an organization administrator can change this.

Request
curl -X PUT {{ api_origin }}/api/v1/profile/ \
  --header "x-api-key: $QUERYMIND_API_KEY" \
  --header "content-type: application/json" \
  --data '{
    "industry": "Retail / e-commerce",
    "business": "We sell online.",
    "keeps": ["orders"]
  }'
Example response
{
  "kind": "api",
  "engine": "postgres",
  "industry": "Retail / e-commerce",
  "business": "We sell online.",
  "keeps": ["orders"],
  "discovered_tables": [],
  "discovered_columns": {},
  "allowed_tables": [],
  "allowed_columns": {},
  "ready": false
}

4. Discover tables and columns

Get the SQL, run it on your database, then post the rows. QueryMind saves the catalog on your API workspace only.

Request — instructions
curl "{{ api_origin }}/api/v1/discover/instructions/?engine=postgres" \
  --header "x-api-key: $QUERYMIND_API_KEY"
Example response
{
  "dialect": "postgres",
  "engine": "postgres",
  "sql": "SELECT table_schema, table_name, column_name FROM information_schema.columns WHERE table_schema = 'public'",
  "instructions": "Run this read-only SQL on your PostgreSQL database, then POST the rows to /api/v1/discover."
}
Request — ingest rows
curl -X POST {{ api_origin }}/api/v1/discover/ \
  --header "x-api-key: $QUERYMIND_API_KEY" \
  --header "content-type: application/json" \
  --data '{
    "rows": [
      {"table_name": "orders", "column_name": "id"},
      {"table_name": "orders", "column_name": "status"}
    ]
  }'
Example response
{
  "kind": "api",
  "engine": "postgres",
  "tables": ["orders"],
  "columns": {
    "orders": ["id", "status"]
  }
}

5. Allow-list

Invented names are ignored. Each allowed table needs at least one discovered column.

Request
curl -X PUT {{ api_origin }}/api/v1/access/ \
  --header "x-api-key: $QUERYMIND_API_KEY" \
  --header "content-type: application/json" \
  --data '{
    "allowed_tables": ["orders"],
    "allowed_columns": {
      "orders": ["id", "status"]
    }
  }'
Example response
{
  "kind": "api",
  "engine": "postgres",
  "industry": "Retail / e-commerce",
  "business": "We sell online.",
  "keeps": ["orders"],
  "discovered_tables": ["orders"],
  "discovered_columns": {
    "orders": ["id", "status"]
  },
  "allowed_tables": ["orders"],
  "allowed_columns": {
    "orders": ["id", "status"]
  },
  "ready": true
}

6. Messages

Ask a question. QueryMind returns SQL. You execute it. Then post rows for a natural-language answer.

Request — ask
curl -X POST {{ api_origin }}/api/v1/messages/ \
  --header "x-api-key: $QUERYMIND_API_KEY" \
  --header "content-type: application/json" \
  --data '{
    "content": "How many unpaid orders?"
  }'
Example response
{
  "id": "msg_12",
  "type": "message",
  "role": "assistant",
  "stop_reason": "sql",
  "user_message_id": 12,
  "conversation_id": 4,
  "conversation_created": true,
  "content": [
    {
      "type": "sql",
      "sql": "SELECT COUNT(*) AS n FROM orders WHERE status = 'unpaid'",
      "executable": true
    }
  ]
}
Request — post result rows
curl -X POST {{ api_origin }}/api/v1/messages/results/ \
  --header "x-api-key: $QUERYMIND_API_KEY" \
  --header "content-type: application/json" \
  --data '{
    "user_message_id": 12,
    "rows": [{"n": 12}]
  }'
Example response
{
  "id": "msg_13",
  "type": "message",
  "role": "assistant",
  "stop_reason": "end_turn",
  "user_message_id": 12,
  "conversation_id": 4,
  "content": [
    {
      "type": "text",
      "text": "There are 12 unpaid orders."
    }
  ]
}

stop_reason: sql means run the SQL. end_turn means the answer is stored.
